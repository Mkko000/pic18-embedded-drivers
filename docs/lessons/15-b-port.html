الدوال بتاعة الرجل الواحدة خلصت. بس مشروع زي الـ LED Chaser بيكتب 8 رجول مرة واحدة. لو عملناها بـ 8 نداءات gpio_pin_write، الليدات مش هتتغير في نفس اللحظة، وفيه 8 فحوصات من غير لازمة. محتاجين دوال للبورت كله. وهنا PORTE هيعمل مشكلة صغيرة لطيفة.

v1: اكتب البايت وخلاص

Std_ReturnType gpio_port_write(port_index_t port, uint8 logic_mask) {
    Std_ReturnType ret = E_OK;
    if (!IS_VALID_PORT(port)) {
        ret = E_NOT_OK;
    } else {
        *(lat_registers[port]) = logic_mask;
    }
    return ret;
}

على PORTC تمام. على PORTE: gpio_port_write(PORTE_INDEX, 0xFF) بتكتب 1 في بتات LATE من 3 لـ 7 اللي مالهاش رجول. الداتاشيت بتقول البتات دي unimplemented، بتتقري 0 والكتابة فيها مالهاش أثر. يعني مفيش ضرر في الكتابة دي بالذات. طب ليه نتعب نفسنا؟

بص على gpio_port_setup على PORTE. في TRISE، البتات العالية مش فاضية: فيها PSPMODE (بت 4) و IBF و OBF و IBOV، وده تبع Parallel Slave Port. لو كتبت 0xFF في TRISE علشان تخلي الـ 3 رجول Input، فتحت وضع الـ PSP من غير ما تقصد، وPORTD كله بقى بيتصرف بطريقة تانية. ده bug حقيقي هيوقعك ومش هتلاقي سببه في الكود بتاع PORTD أبدًا.

اقرا السطر المهم كده: خد الريجستر، وامسح منه البتات الموجودة بس (& ~valid)، وحط مكانها القيمة الجديدة بعد ما تقصّ منها أي حاجة برّه الماسك (value & valid). على PORTC الماسك 0xFF، فالسطر ده بيساوي كتابة عادية. على PORTE بيحمي البتات العالية. وعلى PORTA الماسك 0x3F مع الكريستالة (RA6/RA7 مش I/O) و 0xFF مع OSC_MODE_INTIO67.

خلي بالكالماسك ده لدوال البورت. دوال الرجل الواحدة (Direct و Struct، وبالتالي الليد) بتعمل نفس القاعدة بطريقة تانية: IS_VALID_PORTA_PIN جوّه IS_VALID_PORT_PIN بترفض RA6/RA7 بـ E_NOT_OK إلا مع INTIO67. يعني الشرط واحد، بس البورت بيقصّ البتات والرجل بترفض النداء كلّه.

ليه helper لوحده؟ لأن 3 دوال محتاجاه (setup و set_direction و write)، ولأن الـ Struct API هيحتاجه برضه. والـ static inline معناها إنه مش ظاهر برّه الملف، والكومبايلر غالبًا هيحطه مكان النداء من غير تكلفة نداء.

القراية والتوجل

*logic = (uint8)(*(port_registers[port]) & port_valid_pin_mask[port]);    /* read */
*(lat_registers[port]) ^= port_valid_pin_mask[port];                          /* toggle */

القراية بتصفّر البتات اللي مالهاش رجول، علشان اللي بيقرا PORTE ميلاقيش RE3 (اللي هي MCLR) طالعة 1 ويفتكرها رجل. والتوجل XOR بالماسك نفسه، فبيقلب الموجود بس.

غلطات مشهورة

نسيت إن الـ mask في direction معناه 1 = Input. gpio_port_setup(PORTC_INDEX, 0xFF, 0x00) بتخلي البورت كله Input، والليدات مش هتنوّر. استخدم GPIO_PORT_ALL_OUTPUT وارتاح.

استخدمت gpio_port_write على بورت فيه زراير وليدات مع بعض. الكتابة مش هتأثر على الزراير لأنها Input، بس هتغيّر الـ LAT بتاعهم، ولو حد خلاهم Output بعدين هيطلعوا بالقيمة دي.

gpio_port_write(PORTE_INDEX, 0xFF). LATE هيبقى إيه في البتات اللي تحت؟

الماسك 0x07 بيقصّ القيمة ويحمي الباقي.

تمرين: gpio_port_write_bits

اكتب دالة gpio_port_write_bits(port, mask, value) تكتب بس البتات اللي في mask، وتسيب الباقي. مثال: (PORTC, 0x0F, 0x05) تكتب 0101 في النص التحتاني من غير ما تلمس RC4..RC7. الـ LED Chaser كان هيستفيد منها لو فيه حاجة تانية على البورت.

اعرض الحل 
Std_ReturnType gpio_port_write_bits(port_index_t port, uint8 mask, uint8 value) {
    Std_ReturnType ret = E_OK;
    if (!IS_VALID_PORT(port)) {
        ret = E_NOT_OK;
    }
    else {
        uint8 m = (uint8)(mask & port_valid_pin_mask[port]);
        volatile uint8 * const lat = lat_registers[port];
        *lat = (uint8)((*lat & (uint8)~m) | (value & m));
    }
    return ret;
}

نفس فكرة gpio_reg_write_masked بالظبط، بس الماسك جاي من برّه ومقصوص بماسك البورت.
