في الجزء اللي فات قرينا كود مكتوب. من هنا ورايح هنكتبه. هنبدأ من فولدر فاضي، وكل ملف هيتولد قدامك، وكل قرار هيبقى ليه سبب. ومش هنكتب الكود النهائي على طول: هنكتب نسخة ساذجة، نشوفها بتقع فين، ونصلّحها. ده بالظبط اللي حصل في الريبو، بس هنا مضغوط في كام درس.

كل خطوة في الجزء ده ليها نفس الشكل: الهدف، الكود (والإضافات عليه متلوّنة أخضر والمشال أحمر)، ليه، الغلطات المشهورة، سؤال، وتمرين صغير الحل بتاعه مستخبي لحد ما تحاول.

الأدوات

تلات حاجات من موقع Microchip، كلهم مجانًا:

MPLAB X IDE: البيئة اللي بتكتب فيها وتعمل build وتحرق. تقيلة شوية ومبنية على NetBeans، بس هي الرسمية وفيها simulator.

XC8: الكومبايلر بتاع شرايح الـ 8 بت. النسخة المجانية فيها optimization أقل من المدفوعة، وده مش هيفرق معانا خالص في الكورس. نزّل XC8 لوحده، الـ IDE مش بيجيبه معاه.

حاجة تحرق بيها أو تجرّب عليها: PICkit 4 أو 5 لو معاك بورد، أو Proteus لو هتشتغل محاكاة. ولو مفيش الاتنين، الـ Simulator اللي جوّه MPLAB X بيكفّي لحاجات كتير، هتشوف فيه الريجسترات بتتغير خطوة خطوة.

خلي بالكثبّت XC8 الأول وبعدين MPLAB X، أو اعمل Tools ← Options ← Embedded ← Build Tools ← Scan for Build Tools بعد التثبيت. ناس كتير بتعمل بروجكت وتلاقي خانة الكومبايلر فاضية وتفتكر التثبيت باظ.

الخطوة 1: بروجكت فاضي

الهدف: بروجكت بيعمل build لـ PIC18F4620 من غير أخطاء، حتى لو مبيعملش حاجة.

File ← New Project ← Microchip Embedded ← Standalone Project. الجهاز PIC18F4620، الأداة Simulator لو مفيش بورد، والكومبايلر XC8. سمّيه pic18-embedded-drivers وحطه في فولدر مساره مفيهوش مسافات ولا عربي. ده مش تكلّف: أدوات الـ build القديمة بتتلخبط في المسافات، والرسالة اللي بتطلع مالهاش أي علاقة بالمشكلة.

اعمل ملف application.c:

#include <xc.h>

void main(void) {
    while (1) {
    }
}

Build. لو طلع BUILD SUCCESSFUL، إنت جاهز. xc.h ده الملف اللي بيعرّف كل الريجسترات بأساميها (TRISC و LATC وكل حاجة) للشريحة اللي اخترتها. مش محتاج تقوله PIC18F4620، هو بيعرف من إعدادات البروجكت.

ليه while(1)؟ لأن الميكرو مفيش نظام تشغيل يرجعله. لو main خلصت، الـ XC8 بيعمل ريست للشريحة وتبدأ من الأول. يعني الكود هيفضل يتعاد من غير ما تقصد، وده مش واضح خالص لو مش عارفه.

الخطوة 2: أول ليد، بالريجسترات على طول

الهدف: ليد على RC0 بتومض كل نص ثانية. من غير أي درايفر.
+#define _XTAL_FREQ 4000000UL
 #include <xc.h>

 void main(void) {
+    TRISCbits.TRISC0 = 0;      // RC0 Output
+    LATCbits.LATC0  = 0;      // تبدأ مطفية
     while (1) {
+        LATCbits.LATC0 ^= 1;   // اقلبها
+        __delay_ms(500);
     }
 }

التوصيل: RC0 ← مقاومة 330Ω ← ليد ← الأرضي. والشريحة نفسها محتاجة كريستالة 4MHz بين OSC1 و OSC2 ومعاها مكثفين 22pF للأرضي، ومقاومة 10k من MCLR للـ 5V، ومكثف 100nF قريب من كل رجلين VDD/VSS.

_XTAL_FREQ لازم يتعرّف قبل ما تستخدم __delay_ms، لأنها ماكرو بيحسب عدد اللفات من السرعة. لو نسيته هيطلعلك خطأ واضح. لو كتبته غلط، مفيش خطأ، بس الوقت هيبقى غلط.

غلطات مشهورة هنا

البروجكت بيعمل build والليد مش بتنوّر خالص: غالبًا الفيوزات لسه مش متظبطة، والشريحة شغالة على أوسيليتور مش موجود. ده موضوع الدرس الجاي.

الليد بتومض بس أبطأ أو أسرع بكتير: _XTAL_FREQ مش زي الكريستالة الحقيقية.

في Proteus الشريحة مش بتعمل حاجة: لازم تدخل على خصائص الـ PIC وتحط Processor Clock Frequency بنفس السرعة، وتختار ملف الـ .hex من فولدر dist/.

نجرّب في الـ Simulator

من غير بورد: Debug ← Debug Main Project. حط breakpoint على سطر LATCbits.LATC0 ^= 1;، وافتح Window ← Target Memory Views ← SFRs ودوّر على LATC و TRISC. كل ما تدوس Continue هتشوف بت 0 في LATC بيتقلب. لو مش شايف حاجة بتتغير، يبقى الكود مش واصل للسطر ده أصلًا.

خلي بالكالـ __delay_ms(500) في الـ Simulator بتاخد وقت حقيقي طويل، لأنه بيحاكي كل تعليمة. وإنت بتجرّب، خلّيها __delay_ms(1) أو استخدم الـ Stopwatch اللي في Window ← Debugging ← Stopwatch علشان تقيس الوقت بالظبط.

شلت while(1) من main. إيه اللي هيحصل؟

الـ XC8 بيحط بعد main قفزة للريست. يعني الكود هيلف لوحده، بس معاه كل التهيئة من الأول، وده بيعمل سلوك غريب.

تمرين: ليدين بيتبادلوا

ضيف ليد على RC1. خليهم يتبادلوا: لما واحدة تنوّر التانية تطفي. سطر واحد في اللوب يكفي.

اعرض الحل 
TRISC &= 0xFC;          // RC0 و RC1 Output، الباقي زي ما هو
LATC   = (LATC & 0xFC) | 0x01;   // RC0 منوّرة و RC1 مطفية
while (1) {
    LATC ^= 0x03;        // اقلب الاتنين مع بعض
    __delay_ms(500);
}

الـ XOR مع 0x03 بيقلب بت 0 وبت 1 بس. ولأنهم بدأوا مختلفين، هيفضلوا مختلفين على طول. لاحظ إننا مالمسناش باقي البورت: &= 0xFC بدل = 0x00.
