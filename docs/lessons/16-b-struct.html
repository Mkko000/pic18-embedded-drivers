الـ Direct API بقى كامل. دلوقتي نضيف الـ Struct API فوق نفس الأساس، ونتأكد إن كل واحد يقدر يعيش لوحده. ده الدرس اللي بيفرّق بين درايفر "شغال" ودرايفر ينفع يتاخد في مشروع تاني.

v1: الطريق السهل (والغلط)

Std_ReturnType gpio_pin_initialize(const pin_config_t *_pin_config) {
    return gpio_pin_setup(_pin_config->port, _pin_config->pin,
                          _pin_config->direction, _pin_config->logic);
}

ولما جربنا ده على XC8 v3 فعلًا طلعت مفاجأة: لو بعت للدالة struct const قاعد في الـ Flash، وفي حتة تانية struct في الـ RAM (الليد درايفر بيعمل كده)، الكومبايلر بيقف عند _pin_config->pin ويقول error (712). الحل في الريبو: أول سطر في كل دالة Struct بقى pin_config_t cfg = gpio_cfg_copy(_pin_config);، وبعدها الشغل كله على cfg.port وcfg.pin. فحص الـ NULL لسه على المؤشر الأصلي.

سطر واحد، ومفيش تكرار. فين المشكلة؟ اتنين.

NULL: لو حد بعت NULL، _pin_config->port بيقرا من عنوان 0. الدالة دي لازم تفحص قبل ما تلمس المؤشر.

الاعتماد: اقفل GPIO_DIRECT_API_ENABLE في الكونفيج. gpio_pin_setup مش موجودة، والـ Struct API وقع. يعني المفتاحين مش مستقلين، واحد فيهم كدّاب.

Std_ReturnType gpio_pin_toggle_logic(const pin_config_t *_pin_config) {
    Std_ReturnType ret = E_OK;
    pin_config_t   cfg = gpio_cfg_copy(_pin_config);

    if (NULL == _pin_config) {
        ret = E_NOT_OK;
    }
    else if (!IS_VALID_PORT_PIN(cfg.port, cfg.pin)) {
        ret = E_NOT_OK;
    }
    else {
        TOGGLE_BIT(*(lat_registers[cfg.port]), cfg.pin);
    }
    return ret;
}
