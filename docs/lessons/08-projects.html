الأربع مشاريع اللي في Projects/ مش أمثلة عشوائية. كل واحد بيضيف فكرة واحدة جديدة على اللي قبله، والفكرة دي هي اللي هتعيش معاك في أي مشروع تاني.

خلي بالككل مشروع فيه main() خاص بيه، وكمان application.c اللي في الروت. في MPLAB X ضيف main واحد بس في كل بروجكت، ومعاه config_bits.c مرة واحدة، والدرايفرات اللي محتاجها. لو ضفت اتنين main هيطلعلك خطأ "multiple definition" ومش هتفهم جاي منين.

01 · LED Chaser: الداتا بدل الكود

8 ليدات على PORTC بيعملوا 5 تأثيرات: Knight Rider، وملو وتفريغ، ومن النص لبرّه، وتبادل (0x55 و 0xAA)، واتنين ماشيين مع بعض. أسهل طريقة كانت 5 لوبات ورا بعض. اللي اتعمل إن كل تأثير بقى جدول frames، وكل جدول ليه سرعة وعدد تكرار:

typedef struct {
    const uint8 *frames;    /* الأشكال، كل شكل بايت لـ PORTC */
    uint8        count;
    uint8        step_ms;   /* × 10 ms */

اللوب الرئيسي بقى بيلف على الجداول وبس، ومبيعرفش أي تأثير بالاسم. عايز تأثير سادس؟ مصفوفة جديدة وسطر في الجدول. ولأن الجداول const، الـ XC8 بيحطها في الـ Flash (64KB) بدل الـ RAM (4KB). جرّب الأداة دي وتخيّل كل ضغطة frame:

02 · إشارة مرور: State Machine

تقاطع بأربع اتجاهات، 12 ليد، وزرار طوارئ. الطريقة البدائية: delay(10000) للأخضر، و delay(3000) للأصفر. المشكلة إن وإنت جوّه delay بعشر ثواني، الشريحة عامية. زرار الطوارئ هيستنى لحد ما الأخضر يخلص.

الحل تلات أفكار مع بعض. الأولى: السلوك كله في جدول.

static const tl_step_t tl_table[ST_COUNT] = {
    /* ns               ew               duration */
    { AXIS(LAMP_G),     AXIS(LAMP_R),    SEC(10) },   /* ST_NS_GREEN  */
    { AXIS(LAMP_Y),     AXIS(LAMP_R),    SEC(3)  },   /* ST_NS_YELLOW */
    { AXIS(LAMP_R),     AXIS(LAMP_R),    SEC(2)  },   /* ST_ALL_RED_1 */
    { AXIS(LAMP_R),     AXIS(LAMP_G),    SEC(10) },   /* ST_EW_GREEN  */
    { AXIS(LAMP_R),     AXIS(LAMP_Y),    SEC(3)  },   /* ST_EW_YELLOW */
    { AXIS(LAMP_R),     AXIS(LAMP_R),    SEC(2)  },   /* ST_ALL_RED_2 */
};

الثانية: اللوب بيلف كل 50ms بس، ويعدّ تنازلي. كل 50ms بيبص على الزرار. يعني الاستجابة أقصاها 50ms حتى لو إحنا في نص الأخضر. الثالثة: الأمان. التشغيل بيبدأ بأحمر في كل الاتجاهات لمدة ثانيتين قبل أي أخضر، والخروج من الطوارئ بيرجع على الأحمر برضه. اللي بيصمم إشارات حقيقية بيفكر كده: لو مش متأكد، أحمر.

جرّب تتخيّل إنك عايز تزوّد 3 ثواني على الأخضر بتاع الشمال. في الطريقة البدائية هتدوّر على الـ delay. هنا بتغيّر SEC(10) لـ SEC(13) وخلاص.

03 · عدّاد باينري: الزراير بجد

8 ليدات بتعرض رقم من 0 لـ 255، و 3 زراير على PORTB: زود، ونقّص، وصفّر. ودي أول مرة الكورس يقرا دخل، فطلعت مشكلتين.

الـ Bouncing

الزرار المعدني لما يتداس، النحاس بيخبط ويرتد كام مرة في أول كام ملي ثانية. الشريحة بتشوفه 0 1 0 1 0 قبل ما يستقر. يعني ضغطة واحدة ممكن تزوّد العداد 4. الحل في الكود: نقرا الزرار كل 5ms، ومنصدقش القيمة الجديدة غير لو فضلت هي هي 4 قرايات ورا بعض، يعني 20ms ثابتة.

if (raw != btn->stable) {
    if (++btn->counter >= DEBOUNCE_TICKS) {
        btn->stable  = raw;
        btn->counter = 0;
        if (GPIO_LOW == raw) {
            pressed = TRUE;             /* falling edge = press */
        }
    }
} else {
    btn->counter = 0;                   /* bounce: restart */
}

الـ Edge

لو بنعدّ "طول ما الزرار LOW"، الضغطة الطويلة هتزوّد العداد 200 مرة في الثانية. الكود بيرجّع TRUE مرة واحدة بس، لحظة التحويل من HIGH لـ LOW. والزراير متوصلة على طول بالأرضي بفضل الـ pull-ups الداخلية اللي في PORTB.

uint8 والـ 256

for (uint8 i = 0; i < 256; i++) { ... }   /* مبيخلصش أبدًا */

الـ uint8 أقصاه 255. بعد 255 بيلف لـ 0، فعمره ما هيبقى 256، والشرط دايمًا صح. العدّاد بيستغل اللفة دي في صالحه: count++ من 255 بتجيب 0، و count-- من 0 بتجيب 255. ده سلوك مضمون في C للأنواع unsigned.

04 · Morse: كل الطبقات مع بعض

بيبعت أي نص كـ Morse على ليد (وممكن بازر عن طريق ترانزستور NPN، زي درس الترانزستور). الديمو بيبعت SOS وبعدين MOHAMMED. وده أول مشروع بيستخدم درايفر الليد مش الـ GPIO على طول، يعني الطبقات الأربعة شغالة.

التوقيت كله مبني على رقم واحد، UNIT_MS:

عايز أسرع؟ المعيار إن UNIT_MS = 1200 / WPM، يعني 20 كلمة في الدقيقة تبقى 60ms. والحروف متخزنة كـ strings من نقط وشرط ("..." و "---")، والحروف الصغيرة بتتحول كابيتال، والرموز اللي مالهاش Morse بتتجاهل بدل ما توقع البرنامج.

جرّب: افتكر SOS. ثلاث نقط، ثلاث شرط، ثلاث نقط. احسب الوقت بنفسك على 150ms ثم قارنه بالتوقيت لما تشغّله في Proteus.

إيه اللي جاي

الريبو فيه أماكن جاهزة في device_config.h لدرايفرات لسه مقفولة: زرار، ADC، تايمرز، UART، SPI، I2C، LCD. أول واحد هيبقى غالبًا درايفر الزرار، لأن الـ debounce اللي في مشروع العداد مستاهل يتنقل لطبقة ECU لوحده. وكل درايفر جديد هيبقى ليه درس هنا.

في إشارة المرور، ليه مفيش __delay_ms(10000)؟

لوب قصير بيعدّ تنازلي بيخلي الكود يعمل حاجات تانية بين كل tick والتاني. ده أول خطوة ناحية التايمرز والإنتربتات.

الزرار بيرتد لمدة 8ms. مع debounce بتاع 4 × 5ms، هيتحسب كام ضغطة؟

الارتداد بيصفّر العدّاد كل مرة القراية ترجع للقيمة القديمة. أول ما الزرار يستقر، العداد يوصل 4 في 20ms ويتحسب مرة واحدة.
