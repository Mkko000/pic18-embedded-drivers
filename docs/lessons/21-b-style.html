قواعد في الكود نفسه

الثابت على الشمال: if (NULL == led). لو نسيت = واحدة، خطأ كومبايل بدل bug.

return واحد: متغير ret ونقطة خروج واحدة. اتكلمنا عنها.

أقواس دايمًا: حتى لو الـ if سطر واحد. bug مشهور اسمه "goto fail" في مكتبة أمان كبيرة كان سببه سطر من غير أقواس.

casts صريحة: (uint8) و (port_index_t). بتقول للي بيقرا "أنا عارف إن الأنواع مختلفة ودي مقصودة".

(void) للنتايج المتجاهلة: علشان النسيان والقصد يبانوا مختلفين.

مفيش أرقام سحرية: GPIO_PCFG_ALL_DIGITAL مش 0x0F. الريبو فيه commit كامل اسمه "add named port/pin mask constants and use them instead of magic numbers".

Doxygen

التعليقات اللي بتبدأ بـ /** مش للزينة. أداة اسمها Doxygen بتقراها وتطلّع منها موقع توثيق كامل. والـ MPLAB X نفسه بيوريك الـ @brief لما تقف على اسم الدالة.

/**
 * @brief   Setup a pin completely (digital mode + direction + initial logic).
 * @param   port       Port index (@ref port_index_t)
 * @param   pin        Pin index  (@ref pin_index_t)
 * @param   direction  GPIO_DIRECTION_OUTPUT or GPIO_DIRECTION_INPUT
 * @param   logic      Initial level, written to LAT before TRIS
 * @return  E_OK on success, E_NOT_OK on an invalid argument
 */
Std_ReturnType gpio_pin_setup(port_index_t port, pin_index_t pin,
                              direction_t direction, logic_t logic);

اكتب الـ ليه مش الـ إيه. التعليق /* set bit */ فوق SET_BIT ملوش لازمة. التعليق /* latch first: glitch-free output */ بيمنع حد ييجي بعدك "ينضّف" الترتيب.

وفوق كل ملف header فيه @file و @author و @brief وحقوق الملكية. اللي في الريبو: @author Mohammed El Sisi و MIT License.

ترتيب الملف

كل الملفات في الريبو ماشية على نفس الأقسام، بعناوين واضحة: Includes، وبعدين Macro Declarations، وبعدين Data Types، وبعدين Function Declarations. في الـ .c: الجداول الداخلية، الـ helpers الـ static، وبعدين كل API في قسم. لما الملفات كلها نفس الشكل، إيدك بتعرف تروح فين قبل عينك.

أنهي تعليق مفيد أكتر فوق CLEAR_BIT(*(tris_registers[port]), pin); في setup؟
